# Note AI — переработанный интерфейс (v2)

Полностью новый дизайн той же функциональности: один файл `index.html` со встроенными стилями и скриптом. Без Tailwind и без ES-модулей — страницы открываются даже через `file://`.

## Что изменилось в дизайне
- Новая тёмная тема «deep space»: индиго-фиолетовые градиенты, стеклянные карточки, фоновое свечение и сетка.
- Типографика: Unbounded (заголовки) + Inter (текст), обе с кириллицей.
- Двухколоночная раскладка на десктопе: слева текст и файл, справа «липкая» панель настроек; на мобильных — одна колонка и плавающая нижняя навигация-пилюля.
- Статус-пилюля в шапке: «Gemini подключён» (зелёная) или «Демо-режим» (янтарная).
- Иконки — инлайн-SVG (lucide-стиль), внешняя библиотека иконок не нужна.
- Новый экран результата: бейджи режима/длины/источника, цветное предупреждение (демо — янтарное, ИИ — фиолетовое), секции с маркерами.
- Улучшения UX: Ctrl/Cmd+Enter запускает обработку, счётчик символов зеленеет после 50, спиннер на кнопке, плавные анимации (отключаются при prefers-reduced-motion).
- PDF.js, Mammoth и Tesseract.js грузятся с CDN лениво — только когда нужен их формат.

## Вся функциональность сохранена
- Ввод текста (от 50 символов), счётчик, очистка.
- Файлы PDF, DOCX, TXT, JPG, PNG, WEBP до 15 МБ; drag & drop; прогресс чтения; OCR (rus+eng+kaz).
- Режимы: краткий конспект, краткий пересказ, главные мысли, простыми словами.
- Длина: очень коротко / коротко / подробно. Язык результата: авто / русский / қазақша / English.
- История в localStorage (`noteai.history.v1`, до 30 записей) — совместима со старыми записями прежней версии сайта.
- Копирование, скачивание TXT, повторная обработка, тосты, удаление записей, очистка истории.
- Демо-алгоритм (частотная выжимка) — как в `js/processor.js` оригинала.

## Интеграция Gemini API через Cloudflare Worker
В скрипте внутри `index.html`:

```js
const WORKER_URL = 'https://wispy-dust-5605.drelor011.workers.dev/';
```

## Главная проблема сейчас: «Ошибка Gemini 400: User location is not supported…»

На живом сайте `https://drelor011.github.io/NoteAI/` цепочка «страница → Worker» работает
корректно (задеплоен новый код, CORS и preflight в порядке). Блокирует сам **Gemini API**:
Google запрещает вызовы из ряда регионов, а регион, где выполняется Cloudflare Worker,
выбирается автоматически и на него повлиять нельзя (Казахстан в списке поддерживаемых
регионов есть, а например России и Гонконга — нет). Лечится это бесплатным
**Cloudflare AI Gateway**, который проксирует вызов Gemini из поддерживаемого региона.

### Шаг 1. Обновите Worker
В `worker.js` (лежит рядом с этим README) — готовая полная замена вашего Worker'а:
белый список Origin, preflight, промпт по режиму/длине/языку, разбор ответа Gemini
и понятные ошибки на русском. Откройте Dashboard → Workers → ваш Worker → Edit code,
вставьте содержимое `worker.js` целиком, нажмите Deploy. Ключ API при этом останется
в секретах — только проверьте, что переменная с ним называется `GEMINI_API_KEY` (или `API_KEY`).

### Шаг 2. Создайте AI Gateway и подключите его
1. Dashboard → **AI → AI Gateway → Create Gateway** — придумайте имя (например, `noteai`).
2. Скопируйте **Account ID** (Dashboard → Workers & Pages, справа) и **ID гейтвея**.
3. У Worker'а: Settings → Variables and Secrets → добавьте переменную
   `GEMINI_BASE_URL` со значением:

   ```
   https://gateway.ai.cloudflare.com/v1/ВАШ_ACCOUNT_ID/ID_ГЕЙТВЕЯ/google-ai-studio
   ```

4. Save / Deploy. Всё: Worker теперь вызывает Gemini через гейтвей, и ошибка региона
   исчезает. Модель при желании меняется переменной `GEMINI_MODEL` (по умолчанию
   `gemini-3.8-flash`), резервная модель при перегрузке — `GEMINI_FALLBACK_MODEL`
   (по умолчанию `gemini-3.8-flash-lite`). Модели 2.5-поколения и старше закрыты
   для новых ключей Gemini — не используйте их по умолчанию.

Проверить без сайта: `curl -X POST <адрес-Worker> -H "Origin: https://drelor011.github.io" -H "Content-Type: application/json" -d '{"text":"Текст для проверки длиной не менее пятидесяти символов..."}'` — должен вернуться JSON с `title` и `sections`.

## Если видите «Ошибка Gemini 404: … no longer available…»

Google закрыл доступ к `gemini-2.5-flash` для **новых ключей** (деепрекация 2.5-поколения;
актуальная стабильная модель — `gemini-3.8-flash`, сентябрь 2026). Ошибка означает, что
в Worker'е зашита устаревшая модель, — сам сайт, ключ и AI Gateway работают нормально.

Что делает обновлённый `worker.js` (обязательно замените им код Worker'а):
- основной моделью теперь стоит `gemini-3.8-flash`, резервной при перегрузке —
  `gemini-3.8-flash-lite`;
- **само-лечение**: если Google в ошибке 404 подсказывает замену («Please update your
  code to use models/…»), Worker сам повторяет запрос с этой моделью — сайт продолжит
  работать даже когда текущая модель устареет снова;
- вызовы идут через прежний эндпоинт `generateContent` — он объявлен legacy, но
  работает; на рекомендованный Google «Interactions API» можно мигрировать позже,
  без спешки.

## Если видите «Ошибка Gemini 503: … high demand…»

Это не поломка: модель Gemini **перегружена на стороне Google** — ошибка временная и
периодически случается у всех бесплатных моделей в часы пик. Тот факт, что вы её видите,
означает, что регион и AI Gateway уже настроены правильно и запрос доходит до Gemini.

Что делает обновлённый `worker.js` автоматически:
- повторяет запрос при 429/503/529 с паузой (2 попытки основной моделью);
- затем один раз пробует резервную модель `gemini-3.8-flash-lite` — у неё отдельная
  емкость, и обычно она отвечает;
- если и это не помогло, возвращает понятное сообщение «подождите минуту и нажмите
  „Повторить"» — ровно это посетитель и увидит в панели на сайте.

Что делать вам: просто нажать «Повторить» через минуту или подставить в
`GEMINI_MODEL` менее загруженную модель (например, `gemini-3.8-flash-lite` как
основную). Лимиты бесплатного тарифа смотрите в Google AI Studio → API keys.

Логика запроса не изменилась: `POST { text: ≤30000 символов, mode, length, lang }` → ответ
`{ title, sections }`. Ошибки показываются панелью под кнопкой «Обработать» с действиями
«Повторить» и «Обработать без ИИ».

## Если видите «Не удалось связаться с Worker»

Это не про интернет (чаще всего). Worker жёстко отвечает заголовком
`Access-Control-Allow-Origin: https://drelor011.github.io` и отклоняет запросы с любых
других Origin (ответ 403 «Доступ запрещён.»). Браузер при этом не может прочитать ответ,
и `fetch` падает с сетевой ошибкой — раньше это выглядело как «Нет связи с сервером».

Типичные ситуации:
- **Страница открыта локально** (`file://`, `localhost`, другой домен) — так и будет. Варианты:
  задеплоить файл на GitHub Pages, добавить свой Origin в белый список Worker'а,
  или нажать «Обработать без ИИ» — страница перейдёт в демо-режим до перезагрузки.
- **Страница на `https://drelor011.github.io`, но ошибка осталась** — тогда дело в самом
  Worker или Gemini. Если текст ошибки «Ошибка Gemini 400: User location is not
  supported…» — это региональное ограничение Gemini, см. раздел выше про AI Gateway.

Как добавить свой Origin — не нужно ничего писать руками: возьмите готовый `worker.js`
(рядом с этим README), он уже пускает `https://drelor011.github.io` и `http://localhost:*`.
При желании расширьте массив `ALLOWED_EXACT` в начале файла.

`?demo=1` в URL принудительно включает демо-режим (удобно для проверки интерфейса без Worker'а).

## Деплой на GitHub Pages
1. Скопируйте `index.html` в репозиторий `NoteAI` вместо старого (старые `js/*.js` и `css/` больше не нужны, их можно удалить).
2. Закоммитьте и запушьте — Pages обновится автоматически.
3. Локально: просто откройте файл двойным щелчком или `python3 -m http.server 8000`.
